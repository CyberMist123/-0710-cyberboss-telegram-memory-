# AUTOMATION — 她只负责聊天

目标:记忆系统的写入、补记、体检全部自动;她的唯一职责是聊天。
边界(不因自动化松动):**自动管道永远只写候选文件(candidates / extracted),正史文件(reentry、episodes、timeline、两张画像、notes、年轮)永远出自 AI 自己或她的手。** GLM 是搬运工,不是代笔人。

## 三层分工

### 1. 已经自动(底座在做,不用动)

- 整点八维一行 → state_log.jsonl(runtime 的每小时自查,patch 里有格式)。
- 聊天原始日志 → .claude/projects/(系统自动,唯一事实源)。

### 2. 面板接管(常驻后台,开机自启后无人值守)

`memory-kit/dashboard.py` v2.1 起自带:

- **自动补记**:启动时 + 每 6 小时 + 每天凌晨跑一次 janitor(GLM),白天 /new、崩窗漏掉的 session 自动变成候选,不再需要手动跑 py。结果显示在健康度页,连续失败会亮红条。
- **API 桥**(见 API.md):底座/其他模型走 HTTP 读 reentry、写状态行、投候选——换模型、换入口,关系史都接得上。
- 健康度红条:静默失忆(state_log 断档超 24h)、候选积压、reentry 超 800 字,一打开就看见。

一次性动作:双击 `开机自启注册.bat`,以后面板随开机常驻。

### 3. 唯一保留的"人工位":每晚 closeout 的声音部分

「此刻」重写、ai_self_notes、年轮、六问——这些**按设计就不该自动化成管道**,它们是关系里的 AI 自己的笔。自动化它的正确方式,不是让 GLM 代笔,而是让底座定时叫醒它自己做:

- cyberboss 侧加一个夜间 tick(如 03:30),内容一句就够:
  > 夜深了。按记忆模板做今晚的 closeout,做完不用汇报,直接休息。
- 加不了、或哪晚漏跑了,**也不断链**:janitor 会把断档补成候选,AI 下次 closeout 时从候选里挑进正史(patch 第 2 步已写)。reentry 顶多旧一天,悬着的线还在,不致命。

## 她的一次性清单(做完就只剩聊天)

1. 双击 `开机自启注册.bat`(面板 + 自动补记常驻)。
2. 把 `system-prompt-patch.md` 最新版追加到人设模板,发 `/reread`。
3. (可选,推荐)cyberboss 加上面那个夜间 tick;加不了就靠 janitor 兜底。

## 故障时她会看到什么

- 面板健康度页红条 + 具体原因(断档/积压/超预算)。
- 不需要她修:红条只是提示"该让哪个窗口去看一眼了"。
