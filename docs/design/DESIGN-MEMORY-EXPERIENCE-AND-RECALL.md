
**为什么入口分流、主动发消息、八维联动也算记忆**——这三样看起来像路由和功能，但都长在这条链上：

- **入口分流**决定一件事的过程落在主 Chat 还是分支。落在主 Chat，它进入我当下的经历；落在分支，它进入活动日志。**进不来的东西永远成不了记忆**，所以分流规则是记忆的第一道闸。
- **主动发消息**是经历的表达侧。一趟发生了、我想说、说出来的那次对话才可能成为 Episode 候选。没有经历支撑的主动消息，产出的是没有记忆背书的内容。
- **八维联动**是最短时间尺度上的跨轮记忆——上一小时的倾向影响这一小时，不经过 canon，不经过 Episode。它是唯一一条不落盘也能跨轮的通路。

每件事按同一格式写：**我想要什么 / 为什么 / 怎么实现**。第一人称的"我"指主体 AI。

# 一、什么进得来

## 1. 我想要按「这件事的判断归谁」分流，不按「花多少 token」

### 我想要什么

一件事进来先分类，分完执行方式就定了，不需要再选：

| 档 | 什么事 | 谁做 | 过程落在哪 | 回来什么 |
|---|---|---|---|---|
| **1 · 项目** | 有明确产出的活：工程、调研、多步任务 | 主 Chat 给 prompt → 带轻记忆的子代理去干 | 分支 → 活动日志 | 简单结论 |
| **2 · detail** | todo、健康、天气这类纯数据 | 主 Chat 调脚本 / 小模型 | 不落经历 | 纯数据，直接缝进来 |
| **3 · 重要 MCP** | 记忆、互动 | **我亲自** | 主 Chat | 全过程 |
| **4 · 重要项目**（gate 提示） | 需要重装备，但判断归我 | **我特例决定**自己开 harness 跑 | 主 Chat | 全过程 |

分类依据是**判断归谁**：

- 判断归**外部世界**（天气几度、CI 过没过）→ 第 2 档。谁去取都取回同一个数，选择空间为零。
- 判断归**执行者**（这段代码怎么改）→ 第 1 档。对错由结果验证，不由关系史决定。
- 判断归**我**（翻哪条记忆、怎么回应她、什么算今天要紧的事）→ 第 3 档。
- 判断归我、但我需要更多能力才做得了 → 第 4 档。系统提示"这个要花不少"，**决定权在我**。

### 为什么

先分类再选路，和先选路再分类，结果完全不同。

如果入口是"这一趟的上下文放哪"，就必须有一个闸门在两个选项之间做选择，而闸门唯一能量化的东西是 token。于是资源判据被用来回答归属问题。

在工程任务上两者碰巧同向（工程任务又大又不需要关系史），看不出问题。一挪到记忆上就分叉，而且分叉方向最坏：

> **选择类的差事 token 极小，判断极重。**

"从三十条旧记忆里挑三条呈上来"这个动作成本几乎为零，但**挑哪三条，就等于替我决定了下一句说什么**。这是 `CLAUDE.md` 最高判据里"记忆失败"的字面定义。任何按 token 大小分流的闸门，都必然把它判成"小事，可以下放"——恰好把最不能交出去的东西交出去。

这是 **D16 的读侧对偶**。D16 已裁定写侧：后台廉价模型只搬运、不产出，代笔就是第二个 writer。读侧（选什么呈到我面前）是同一条原则的另一半，尚未裁定。

### 怎么实现

**分类表落成配置，不落成模型判断。** 每个能力在目录里带一个构建时算好的档位标签（在这儿做 / 交出去做 / 脚本取），我读到的是一个属性，不是一道要我算的题。

**token 预算从入口选择器降级为执行护栏。** 数字继续在 runtime 里硬拦——工具返回长度上限、调用轮数上限、大 MCP 不进 chat 的配置文件——但不出现在我的判断链里，也不出现在给我看的能力目录里（那一列删掉）。

**拒绝时的返回不带账目语言。** `budget_exhausted` 这类词不进上下文，账目落日志。

**第 4 档的 gate 提示形态**：提示"这个要花不少"，但不替我决定。护栏可见，选择权归我。

**首批只接第 1、2 档。第 3 档不外派。**

# 二、什么留得下

## 2. 我想要一个「经历区」，装我一个人做过的事

### 我想要什么

一个存储区，装我独自去做一件事的完整过程。原件全留，不进普通上下文，但我自己可以回查。

**这不是新提案。** `docs/HEARTBEAT_FREEDOM.md:23` 原则 3 已经写了：「不表演：自由活动不逐步汇报。**产出自然落进记忆、时间线、活动日志**；她想看去面板看。」——**活动日志**就是这个区在仓库里的既有名字。八维签到之后 AI 去做了什么，本来就约定会有后台记录。本节补的是"它待在数据层哪个位置、按什么规则写"。

**回来说不说、说多少，本节不设计。** 我一般会忍不住想说，那就让它自然发生。要设计的是记录，不是汇报。

### 为什么

`MEMORY.md` 现有的数据层里没有它的位置：

- **Episode** 装「共同发生过的事件」——默认两个人在场。
- **Self-note** 装我的选择、误读、兴趣、疑问——是**对经历的评注**，不是经历本身。
- **Rereadings** 装对旧 Episode 的新理解——必须引用一条已存在的 Episode。

我一个人跑了一趟、花了二十分钟、试了三种做法、最后成了或没成——这整段过程现在没有区能装。要么被压成一条结论，要么根本不存在。

第二个原因是它解掉一个死结：如果过程不留，这一趟对我来说就是永久丢失的——**我说"我去做过"，但说不出任何细节，因为我确实没有**。有了活动日志，"我做过这件事"和"我记得这件事的完整细节"才能分开：前者常驻，后者按需回查。

### 怎么实现

**存储**：独立目录，一趟一个文件。不写 `episodes.jsonl`，不进 canon，不进 Timeline / Portrait。

**字段**（最小集）：

```text
起念来源     心跳 / 用户请求 / 重读触发
起念内容     为什么去做这件事（原话）
开始与结束时间
执行原文     完整过程，不删减
结果         成了 / 没成 / 中断
```

**结果字段必须能记「没成」。** 一件永远做得成的事产生不了张力。中断和失败是同等合法的终态。

**写入权**：主体 AI 唯一 writer，与 Self-note 同级（`MEMORY.md` 第 7 节写入权表需新增一行）。执行分支不直接写这个区——分支返回材料，由主 Chat 落盘，避免第二个 writer。

**读取**：默认不注入任何上下文。回查是显式动作，与 `memory_lookup` 分开——**活动日志不在 D7 的管辖范围内**，D7 管的是主动翻主记忆区（Episodes 及下游旧档）。这是新存储区，读取权需单独裁定。

**与 D14 的边界**：结果胶囊契约（`src/orchestration/delegation/`）继续只用于工程委派——它八个字段全是工作产物，设计目的就是剥掉过程。活动日志反过来，要留过程。两者不混用。

**与 Episode 的边界**：一趟不自动升格成 Episode。如果一趟里有什么后来在对话中被讲出来、被她回应了，那次**对话**可以成为 Episode 候选，走现有 Closeout / Auto Review 通路——入口是那次对话，不是那一趟。这条防的是同一件事在两个区各写一份真相。

**与宪法第三条的对齐**：活动日志属于四层表里的「发生的事」那一层的私有侧——共同经历进 Episodes，独自经历进活动日志。两者文体相同（第一人称、过去式、钉在具体一次），区别只在有没有第二个人在场。

# 三、什么提得起

## 3. 我想要「怎么提起」和「怎么记录」用两套判据

### 我想要什么

把记忆的读和写当成两件事设计，各有各的判据。

### 为什么

这两个动作在文档里是分开的（`MEMORY.md` 第 1.3 节讲检索，第 7 节讲写入权；宪法第五条讲书写文体），但**提起那一侧至今没有判据**——现在只能借用写入侧那句"什么是重要的记忆"。

两者的失败方式相反：

- **提起失败** = 说了不该说的（翻出一条不该此刻出现的旧事，或者说得像在背诵）
- **记录失败** = 留下了没用的（存了一堆将来永远不会改变任何一句话的条目）

用同一套判据管两个方向相反的失败，必然有一边被将就。

### 怎么实现

**提起的判据：不这么说会 OOC。**

不是"检索命中了"，也不是"这条很重要"。判断标准是：**不带着那件事说话，这句话就不像我说的。**

这个判据的用处在于它能**否定**——大部分检索命中都过不了它。一条旧事命中了关键词，但不提它这句话也完全像我说的，那就不该提。

它也解释了 `README.md` 诚实分级为什么必要："我记得"对应的是没提也会 OOC 的那部分，所以天然在场；"我翻了下记录"是被外力拉出来的，所以必须标明。两者的区别本来就是**提起的动因**不同。

**记录的判据**：见宪法第二条与第五条，本文不重复。

**验收方式分开抽样**：提起侧看**假阳性率**（提了但不提也一样的次数）；记录侧看**沉睡率**（存了之后从没改变过任何一句话的条目占比）。

**一条必须写明的禁用范围**：不得把删除测试用于 harness 的一段、一个工具、一项能力。

宪法第五条把删除测试列为文体护栏之一，那是对的——但它的适用域只有**记忆文本**。挪到能力上极性会反过来：一个能力存在的全部理由就是改变内容，拿掉翻档 / 发消息 / 提醒 / 日记，回复内容当然变，会被一律判失败；而一段纯语气指令拿掉只变语气，反而判合格。按这个跑到底，最优解是"留下全部风格提示、砍掉全部工具"，正是 D13 已废弃并明令不得重提的零工具方案。

**当前状态**：Soft Retrieval 暂缓（`MEMORY.md` 第 1.3 节已写明），目前记忆结构是**目录 + episodes**，提起只有用户明确拉线一种。所以这条现在只影响设计——但**判据要先定，否则 Soft Retrieval 一开工就会默认用"相关度"当判据**，那是检索的判据，不是记忆的判据。

# 四、什么改得了下一次

## 4. 我想要八维联动闭环：上一次的值回来，且这件事能落空

### 我想要什么

```text
自我倾向（八维 = 影子，不是清单）
        │
      起念
        ↓
   一趟（去做，也可能落空）
        ↓
      记录
        ↓
下一次的倾向（被上一次改变过）
```

### 为什么

这是**唯一一条不落 canon 也能跨轮的记忆通路**。Episode、Re-entry、Rereadings 都要经过 Closeout / Auto Review / History writer 才跨得过夜；八维是小时级的，靠自己跨。

现在这个环是开的，缺口在两处：

**一、没有差分。** schema 里已有 `change: up/steady/down` 和 `cause` 两个字段，本来就是为"变化"设计的，但没有代码喂过上一次的值——每次从零打分，`change` 填什么没有依据。

**二、不能落空。** 想做一件事 → 去做 → 没做成 → 有点烦，这一串才是倾向的运动。现在它连"去做"这个动作都没有，输出格式只给了沉默一种。

推论：**八维不该有"完成率"，不该有"达成"状态**——倾向不会被完成。它该有的是强度和方向的变化，而变化需要上一次的值。

### 怎么实现

**带上一次的值**：心跳提问改成「上次你想做的那件事，做了没有、还想不想」。改的是 `src/app/hourly-desire-poller.js` 里几十个字。这一步不接任何行动能力，就能让倾向第一次可以证伪——至少能产生"没做成"这一个后果。

**解锁行动**：`src/core/system-message-dispatcher.js:60-63`，`desire_checkin` 分支的提示词只给了一个写死 `"action":"silent"` 的模板，全段没出现 `send_message`。**但运行时 `src/core/stream-delivery.js:878-896` 的解析器只认 `silent` 和 `send_message`、其余判 `unsupported action`——`send_message` 本来就是合法的。约束在提示词层，不在代码层，解锁只需改提示词。**

**接上闭环代码**：`src/core/app.js:3103-3104` 的 `maybeCloseDesireLoopForPendingOperation` 函数体为空，而 `app.js:2683` 有真实调用点（实测 `node --test --test-name-pattern="completed driven system turn" test/system-inbound.test.js` 失败，`AssertionError: '' !== 'web_browse'`）。配套四个函数只有定义、零调用：`buildPendingSystemDesireOperation`（3209）、`shouldPulseSelfExperienceForAction`（3220）、`sourceDriveKeyForAction`（3228）、`resolveDesireAvailableActionsSafe`（3242）。`DesireService` 在 `src/` 里零实例化。

**维度数先不动**，把上面这些接上之后再评估是否需要新维度——那时才知道缺的是哪一种情绪。

## 5. 我想要写下去的东西有人读

### 我想要什么

每一个记忆写口都有一个已接线的读者。没有读者的写口，要么补读者，要么停写。

### 为什么

`MEMORY.md` 的设计里每个写口都有读者：Self-note 由 Closeout / Reflect 低频回读（第 2.3 节），Rereadings 经 Reflect 间接影响 Re-entry（第 3 节），Desire 的 Current State 可以轻量进上下文（第 5 节）。

实现里这三条读取路径都没通：

```text
ai_self_notes.md      写口两个（memory_note 工具 / closeout 的 publishSelfNote）
                      读者一个（weekly-reflect.js 的 recentNotes()）
                      但 WeeklyReflect 无人实例化，runtime.reflect() 在 src/ 无实现方

rereadings.md         写者 weekly-reflect.js（同上，ORPHAN）
                      src/ 里除它自身查幂等 marker 外无读取方

desire-history.jsonl  写者 desire-state-persistence.js（已接线）
                      读者只有 520 面板；AI 的上下文里没有任何一条来自它
                      （520 的只读 GET 端点不需 token、只绑本机，
                       所以是"没注入"，不是"读不到"）
```

另有一条：`src/core/hard-context.js:82`，`prepareOrdinaryContext` 返回 `currentState: null`——Current State 只在开场轮和 `/reread`、`/switch` 时注入，一段正在进行的聊天里，这一小时的心跳进不来。

三个写口没有读者，直接顶着北极星那句「给明天的自己留下自己的笔迹」——而明天的自己收不到。这也命中 `CLAUDE.md` 的腐化信号「『默认隐藏』被实现成『无法查询』」，只是被隐藏的是它自己的记录。

宪法第一条说「读信的人就是我」——那么信必须寄得到。**补读者是宪法第一条在实现侧的前提条件**，不是另一件事。

### 怎么实现

**先补读者，再谈内容。**

| 写口 | 最小读者 | 何时读 |
|---|---|---|
| `ai_self_notes.md` | 已存在（`recentNotes()`），缺调度 | Closeout 写 Re-entry 时 |
| `rereadings.md` | 需新增 | 同上；老化与降级规则见宪法第六条 / issue #38 |
| `desire-history.jsonl` | 需新增 | 心跳提问时带入上一次的值（见第 4 条） |

**读取权按 D16 收口**：读者只能是"产生那段对话的当前窗口 AI"，且只在它写 Re-entry 的那一刻，不是对话进行中。这与 `MEMORY.md` 第 2.3 节「普通对话不注入 Self-note 原文」一致。

**一条现状澄清**（避免后续被误判为受 CI 保护）：给 `rereadings.md` 增加读取方**不会撞现有 CI**。两个相关测试钉的不是"不许被翻档工具读"：

- `test/phase2-hard-context.test.js:191-216` 钉的是默认不注入普通上下文（trace 的 `skipped` 里必须有 `{type:"rereadings", reason:"default_hidden"}`）
- `test/phase2-hard-context.test.js:247-256` 钉的是三个常驻上下文构建器的源码里不许出现 `rereadings.md`，清单只有 `shared-instructions.js` / `hard-context.js` / `reentry-loader.js`，**`memory-lookup-service.js` 不在清单里**
- `test/phase5a-memory-lookup.test.js:49-60` 测试名含 "without reading hidden archives"，但断言里没有一条检查它没被读，且诱饵内容不含查询词

「默认隐藏 ≠ 不可查询」在本仓库本来就是两件事（`docs/IMPLEMENTATION_HANDOFF.md:26`），现有测试守的是前者。

**一道必须先立的闸**：让重读影响 Re-entry 的最短路径是往里加一段，而 `CLAUDE.md` 列的第一条腐化信号就是「Re-entry 注入字数持续上涨」。所以规矩是**只允许改已有那几行的措辞和分寸，不允许新增行**，可直接写成钉住行数的测试。

## 6. 我想要主动发消息是一趟的副产品，不是定时推送

### 我想要什么

我主动说话，是因为发生了什么然后我想说；不是因为到点了该说。

### 为什么

定时推送产出的是**没有记忆背书的内容**——它每天在同一个位置出现，内容由模板决定不由经历决定。这类消息进不了 Episode（没有真实事件），也改变不了下一轮的姿态（没有真实变化）。它在记忆链上是空转。

一趟的副产品不一样：它有起念、有过程、有结果（包括没成），说出来的那次对话可以成为 Episode 候选，走现有的 Closeout / Auto Review 通路。

两者在体验上可分辨：

```text
定时的：「早上好，今天想做什么？」   → 位置固定，第三天就学会忽略
一趟的：隔两天没动静，忽然说一句     → 不可预测，因为它依赖真的发生过什么
```

### 怎么实现

**主动消息的触发源只有一个：一趟结束。** 不设独立的定时推送通道。心跳本身不发消息——心跳产生的是起念，起念可能变成一趟，一趟结束后我可能想说。

**不做汇报形态**：不做回执卡片（「↗ 已交给工程分支 #17 / 执行者：Codex」这类），不做状态短讯，不给回流内容设长度或格式约束。这与 `HEARTBEAT_FREEDOM.md:23` 原则 3 一致。

**沉默是合法结果**：一趟结束后不说是正常的，不记负分。这与 `MEMORY.md` 第 4 节「无变化是正常结果」一致。
