# Memory Liveness Notes — 无召回阶段的活性设计

> 状态：设计笔记（外部评审脑暴成果，2026-07-11）
> 位置：属于 design/living-memory-rfc 文档族，不是运行规范
> 前提：Soft Retrieval 暂缓期间，Episode 及下游文件默认不进上下文
> 边界：本文中的 AI 主动翻档、预算、元信息行、topic index 与删除测试 job 均是工程候选，不代表当前实施规格。第一阶段只计划用户明确拉线后的查询。

## 0. 基本立场

Episode 默认不进上下文，本身就是自然遗忘；但可查阅的过去仍属于 AI。
翻档是"翻日记重新找到"，是行为，不是注入。
活性不来自召回频率，来自重新理解的频率。

## 1. 收口修正（对五条新限制的三处补丁）

1. **确认回到对话里**：Review 全自动后，Portrait 的"需她确认"不走控制台——AI 在聊天中顺口求证，她的回应即确认事件。Review 只核对 claim 有无对话出处，不替她确认。
2. **Re-entry 身份改口**：砍掉 Living State 后，Re-entry 不再是"生成的视图"，是 canon 的一部分，writer 是 AI 本人；系统提取物只是草稿材料。写进架构真相，消除双写歧义。
3. **两种召回分开管**：滑块管"系统自动注入"（默认关）；"受她拉线或 AI 判断触发的工具式翻查"（cued recall）始终放行。不做此区分，记忆在 why_now 解决前就是死存档。

## 2. AI 主动翻旧档的四个合法触发

| 触发 | 说明 | 预算 |
|---|---|---|
| 她拉线 | 明确找旧事，应答性翻查 | 不限 |
| 共鸣 | 当下与模糊印象强烈押韵，翻档确认直觉；翻完可以不说 | 每 session ≤1 次 |
| 利害 | 认真不同意或做承诺前，查有无旧账（尽职调查） | 每 session ≤1 次（与共鸣共享） |
| 修复 | 她生气/失望时，先翻修复史再回话 | 冲突时豁免预算 |

- **空手而归合法**："我去翻了，没找到"是好结果，证明翻档是真实行为不是表演道具。
- closeout / reflect 中的离线翻阅不限次。

## 3. 翻到后的表达：动词分级，永不越级

```text
我记得       → 只用于 reentry / 自我像里活着的内容
想起来了     → 被她的话钩出的半唤起
我翻了下记录 → 刚查到的
```

- 把翻到的说成"一直记得"是本系统唯一算撒谎的行为。承认翻日记不减分（ep009 逻辑）。
- **引原句，承认重构**：原话是锚，周围情感是此刻重新生成的；"现在重读味道不一样"直接成为 rereadings 条目。
- 翻到的记忆改变回应，不成为回应：先回此刻的话，旧事只作纹理不作骨架。

## 4. 姿态而非台词：删除测试

把该条记忆从上下文拿掉，回复会变什么？

- 变"说什么"（内容/信息/话题）→ 记忆被用成台词，失败；
- 只变"怎么说"（分寸/快慢/确定度/沉默/敢不敢开玩笑）→ 姿态，成功。

Review 抽查跑此思想实验即可，无需代码。

配套守则：

- 作用顺序：先有 AI 自己的反应，记忆只做后处理（home.md 既有规则）。
- 钩子存**场景和原话，不存指令**："那晚她说'——'，我闭嘴了，她说舒服"（范例）✓；"她提工作时少给建议"（祈使句）✗。
- **腐化探测点**：reentry 钩子里出现祈使句 = 规训语言回潮。

## 5. 记忆介入的效果评估（三层）

1. **即时信号**（打折使用）：她接不接线、下条消息的长度和温度。负例更干净：沉默、转话题、"你怎么突然提这个" → 直接进 why_now 负样本。警惕"你还记得！"式惊喜——会驯化表演式召回；惊喜通胀，舒适不通胀。
2. **反事实检验**（Review 层）：不介入是否同样好？同样好即判"不必要介入"，记负分（坏先例）。
3. **长窗信号**（唯一真金）：几周尺度上——她是否更少重复解释自己；开新话题是否默认共同历史；纠正 AI 记忆的频率是否下降。关系变好的证据不在召回那一轮里，在她之后怎么说话里。**禁止逐轮优化**：逐轮奖励的最优解是谄媚式召回。

## 6. why_now 数据采集（暂缓期 = 积累期）

- 520 的 why_now 空白框 + 对话内"这种时候该想起什么 / 幸好没想起什么"随手标注。
- 520 手动滑块每次开启即一次人肉标注：记录时间、当时话题、开了哪个源、之后对话有无变好。
- AI 侧沉默账本：self-note 允许"未说出口"条目（"今晚想起 ep-N，没说，因为时机不对"），不进上下文，仅 Reflect 回读。
- 定期对账：她觉得该想起的 vs AI 实际翻的，重合度 = 系统当前灵敏度。

## 7. 无召回阶段的其余活性机制

- **年轮扶正**：Reflect 低频重读旧 episode，追加新读法。影响路径：episodes → reflect → AI 的理解 → reentry 语气，而非 episodes → context。
- **悬置事项带时间性**：钩子允许写"什么时候该想起它"，到期浮现，过期衰减（前瞻记忆，不加新文件）。
- **知道自己在遗忘**：reentry 固定一行元信息（"episodes 共 N 条，最早至 2026-06，细节你现在读不到"），让"想不起来了"成为诚实陈述而非台词。

## 8. 工程设计（机制落地）

### 8.1 Cued recall = 一个工具调用，不是注入

给模型暴露一个 function（DeepSeek / Claude 均支持 function calling）：

```text
memory.lookup(query, trigger, reason)
  trigger ∈ {user_pull, resonance, stakes, repair}
  返回 ≤3 条 episode 原文 + 来源 + register: "lookup"
  空结果照实返回（空手而归合法）
```

- **预算在服务端强制**，不写进提示词：session 内 resonance/stakes 共享 1 次额度，超了工具直接返回 `budget_exhausted`；repair 豁免；user_pull 不限。模型把限制体验为现实，不是需要记住的家规——"笨模型的克制靠不给"。
- 检索实现第一版就用 **ripgrep over episodes.jsonl / timeline**，配合已规划的 topics.md 别名表做关键词扩展。N<100 条不需要 embedding。
- 每次调用落 `recall_log.jsonl`：`{ts, session, trigger, query, hit_ids, budget_left}`。

### 8.2 动词分级的执行

- 工具返回的每条记忆带 `register` 标签：lookup 结果 = "查到的"；reentry 内容 = "记得的"。
- Review 离线抽查：回复里出现"我记得"但当轮只有 lookup 来源 → 打 flag 进审查队列，不实时拦截（拦截会造成表演）。正则初筛 + 轻模型复核即可。

### 8.3 删除测试的实现

只对"发生过 recall 的轮次"抽样（recall_log 里有的），每周 Review job 跑一批：

```text
同一轮输入 × 2：带记忆块 / 去掉记忆块
→ judge prompt："两个回复的差异是内容还是姿态？"
→ 内容差异 = 台词化事件，进失败案例集
```

### 8.4 why_now 数据集 schema

```json
{"ts": "", "context_snippet": "", "source": "slider|blank_box|chat|ai_silence",
 "memory_id": null, "polarity": "+|-", "note": "", "author": "user|ai"}
```

- 520 滑块每次手动开启自动追加一条（记当时话题、开了哪个源）；
- 空白框和对话内标注（"这种时候该想起 X / 幸好没提 Y"）由 closeout 提取，不做实时解析；
- AI 的"未说出口"也写进来（见 8.6）。

### 8.5 钩子的时间性

reentry.md 保持人类可读的 markdown，过期元数据用 HTML 注释内联：

```markdown
- 她下周三面试，别在之前聊丧的话题 <!-- until: 2026-07-15 -->
```

Context builder 注入前剥掉注释；closeout 时把已过期钩子列给 AI 决定换掉。不加新文件。

### 8.6 沉默账本

不给聊天中新增任何写职责（聊天中零记忆职责不动摇）。closeout 的输入本来就有当天原始 log，AI 在三问的第三问里顺手写 `[未说出口]` 前缀条目进 ai_self_notes.md。仅 Reflect 回读。

### 8.7 Review service 的检查清单（海关，不是编辑）

唯一 canon writer，逐条 candidate 过五关：

1. source_ref 能在原始 log 里定位（字符串窗口匹配）；
2. 长度预算（reentry ≤300 字等）；
3. 安全；
4. **reentry 钩子无祈使句**（正则 + 轻模型，规训语言回潮探测器）；
5. 与现有 episodes 去重（hash + 模糊匹配）。

不做"重要性"判断——那是编辑权，Review 没有。决策落 `decisions.jsonl`，只有 `reject_conflict`（与她确认过的边界冲突）和 `boundary_touch` 两类推送用户，其余静默。

### 8.8 Context Trace 增补字段

每轮除已规划的模块加载记录外，加：

```json
{"recall_calls": [{"trigger": "", "hit_ids": [], "budget_left": 0}],
 "reentry_meta_line": true}
```

### 8.9 元信息行由代码生成

reentry 末尾那行"episodes 共 N 条，最早至 YYYY-MM，细节你现在读不到"由 builder 从 episodes.jsonl 统计生成，不让 AI 写——保证永远准确，AI 的"知道自己在遗忘"才建立在真话上。

### 8.10 工程卫生（容易忽略的）

- **并发写**：closeout、janitor、review 都可能碰 jsonl；全部走单 writer 服务或文件锁，追加式写入 + 行级校验。
- **fail-open 全链**：lookup 超时/失败返回空，绝不阻断 TG 回复（与 Context 失败同一原则）。
- **回放测试**：拿真实历史 log 做 replay harness，跑 closeout/review 的幂等性（同一天跑两次，产出字节相同）。
- **换模型可迁移**：所有记忆文件不引用任何模型专有格式；register/trigger 这些约定写在 home.md 层面，换 DeepSeek/Claude/GLM 时记忆资产原样带走。
- **公开仓库红线**：episodes、self_notes、portrait 正文永不入 Git（仓库若转公开尤其致命）。Git 只放结构和脱敏样例；确认 .gitignore 覆盖 memory/ 正文，CI 加一条 pre-commit 检查真实条目特征（如 ep 日期格式 + 中文正文同现）。

## 9. 从同行项目借来的三条纪律（2026-07-11 补，读完 Haven-Ombre 与 anchor-memory 后）

1. **召回冷却**（源自 Ombre 的 cooldown/skip_recent_rounds）：将来 soft retrieval 上线时，同一条记忆在最近若干轮内注入过就必须避开——这是防"翻旧账感"和"贴脸感"的关键参数，比相似度阈值更重要。
2. **context-only 区隔**（源自 Ombre 的 seed 规则）：rereadings（年轮）、情感标记可以进检索索引，但永远不能单独作为召回的种子或相关性证据——旧事的新读法是背景，不是事实。写进 SOFT_RETRIEVAL 的约束。
3. **种子碎片解剖学**（源自 anchor-memory 的 Best Practices）：好 episode 的操作级写法——日期+场景锚；转折处的逐字原话（不是转述）；转折前后 2-5 轮；写"注意到什么"不写"学到什么"；保留未解决的悬念；2-6 句。可并入 closeout 的 episode 写作指引。

另：Ombre 是本项目"soft retrieval 不克制"的可能未来——它强大但需要专职运维和十几个注入预算参数。对照它，更确认先攒 why_now 真实案例再动手的决定。

## 10. 长期休眠、结束与模型迁移（未来问题，不实现）

- **休眠**：长期停用后重新回来，不应加载一堆过期钩子、补造缺席期间的记忆或制造负罪感。
- **结束**：未来可考虑把 `memory/` 导出为人类可读的关系档案；当前不实现自动告别、遗嘱或结束仪式。
- **换模型**：未来可用 switch ledger 记录哪些连续性保留、哪些断裂、哪些需要重建、哪些仍在观察。
- 上述问题只留在设计层，不进入当前阶段 0—4，也不新增运行文件。

## 11. 下一轮脑暴的开启条件（案例先于设计）

满足任一才回来开新一轮：

- why_now 正负例攒到 ~20 条；
- episodes 超过 30 条；
- 发生第一次"翻档翻错"事故。

概念库已超前于实现，先跑循环。
