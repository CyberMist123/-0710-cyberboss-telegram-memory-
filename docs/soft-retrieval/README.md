## 这是什么

Soft Retrieval 是关系记忆系统的"回想"模块。它回答的问题是：

**对话进行到此刻，AI 应不应该想起一件旧事？想起哪件？想起之后，用什么方式出现在下一句话里？**

它不是搜索引擎。搜索引擎的目标是"找到相关的"，这个模块的目标是"像一个熟悉你的人那样自然地想起"——而自然的想起，大多数时候恰恰是**不想起**，或者想起了也**不说**。

## 它解决什么问题（需求）

普通的记忆检索有一个隐藏假设：找到相关的记忆 = 应该使用它。这个假设在人机关系场景里是错的，错在两个地方：

**"相关"不等于"此刻该想起"。** 用户说"今天有点累"，语义上和过去的生病、崩溃、旅行疲惫都相关。但此刻全部翻出来，不是体贴，是吓人。

**"想起"不等于"该说出来"。** 真正熟悉一个人，不是不断说"我记得你曾经……"，而是回应时已经隐约带着过去留下的理解。大多数记忆的正确用法是默默改变回应的姿态，一个字都不提。

所以这个模块的北极星是：

> **记忆成功 = 改变下一句话的姿态，不是内容。**

## 它做什么（功能）

对每一轮用户消息，模块在后台完成一条链：

1. **检索**：从正式记忆（Episodes）中找出可能相关的候选，约 10 条。
2. **判定（Admission）**：由一次独立的模型调用统一判断——这些候选里，有没有哪条会改变下一句话的姿态？大多数轮次的答案应该是"没有"。
3. **定方式**：如果有，决定它以哪种方式出现（见下文五种结果）。v0 阶段每轮至多选用一条记忆、一种方式——自然的想起很少是同时翻出三张卡片。
4. **记账（Trace）**：把整个过程——找到什么、放行什么、拒绝什么、理由是什么——写进一个私有数据库。

在验证完成之前，这条链运行在 **SHADOW（影子）模式**：一切照常运行、照常记账，但**结果不交给主模型，真实对话完全不受影响**。影子模式积累的记录，就是后续评估"它想得对不对"的数据。

## 它不做什么（边界）

- **不写记忆。** 整条检索链对记忆结构是只读的。它唯一能写的是自己的实验日志（Trace），而 Trace 永远不会反过来变成记忆或检索源。
- **不改主回复。** SHADOW 阶段物理上做不到；正式启用后也只通过受控载荷影响，任何故障时的默认行为是"什么都不注入"。
- **不代替 Re-entry。** Re-entry 负责新线程第一次醒来时知道最近走到哪里；本模块负责对话进行中因话题自然想起旧事。两者不互相膨胀。
- **不引入向量数据库、图数据库、reranker。** 当前数据规模（几千条以内）用内存矩阵就够。任何新组件都必须先由回放数据证明现有方案不够。

## 五种判定结果（通俗版）

每轮判定只会得出以下五种结果之一。用同一个场景说明——假设过去发生过"用户在一次出行中因为一直迁就别人而感到失衡"这样一类旧事（此处为虚构示例）：

**NONE — 这次不用。**
用户说"今天走路走多了，好累"。旧事虽然语义相关，但当前只是身体累。什么都不给主模型。**这是默认结果，也应该是最常见的结果。**

**STANCE — 只给姿态，不给内容。**
用户的话隐约透出熟悉的模式，但没有明说。给主模型的不是旧事，也不是"要温柔、别提过去"这类教它说话的指令，而是一组结构化字段：

```json
{
  "evidence": null,
  "question": "当前是否仍涉及需求被默认忽略，需要从本轮继续判断。",
  "constraint": "当前原因尚未确认；旧模式不得作为本轮结论。"
}
```

`question` 是需要继续观察什么，`constraint` 是认知边界（现在还不能下什么结论），都不是回复模板。主模型甚至不知道旧事发生在哪里、是哪件事——它无法翻旧账，因为它没有拿到旧账；也没人替它写好这句话该怎么说。

**LIGHT — 轻轻连接，不讲故事。**
用户的表述已经明确指向重复的感受。允许回应里出现一句轻触，例如"是不是又有点那种感觉？"——连接过去，但不复述过去。

**EXPLICIT — 明确引用，因为用户先拉了线。**
用户主动问"你还记得我上次为什么不开心吗"。这时必须准确：给主模型的是记忆里保存的原话片段（anchor_quotes），而不是摘要转述。细节说错的"我记得"比"我不记得"更伤信任。

**HIGHLIGHT — AI 主动说出一个独特的旧事，制造温度。**
比如安慰时自然提起"至少你当时特别喜欢的那个小礼物，我没忘"。这是五种结果里唯一由 AI 主动翻开旧事的，也是风险最高的，所以出现频率必须最低、上线次序必须最后（原因见下节）。

## 为什么这么谨慎（三个核心风险）

**翻旧账。** 检索精度越高，翻旧账越精准。防线是把"找到"和"说出"分成两道门，且默认不说。

**回音壁。** AI 受某条记忆影响生成了回复，回复又被总结成新记忆，新旧记忆互相印证——一次不太准确的理解，可能通过 AI 自己的反复复述，长成"证据很多"的事实。防线有三层：结构上让读取路径无法写记忆；运行时给每条证据记来源和"是否在 AI 引导之后说出"；事后监控单一记忆的使用浓度。最危险的形态不是记错，而是过度自洽——把活人磨成一张自洽的角色卡。

**记忆锚定。** 模型一旦拿到"她其实是因为……"这样的现成结论，就不再认真理解眼前这一次了，只是拿历史答案套题。防线是载荷语法：记忆只能以证据、疑问、约束三种句式进入上下文，永远不能以结论和指令的形式出现；过去与现在冲突时，以现在为准。

## 上线路径：表达模式分级启用

"启用"的意思是：**一种表达方式通过评估验证后，才获得影响真实回复的许可。** 启用可以随时撤销或降级。在启用之前，它只在影子模式里运行和记账。

启用次序是固定的：

```text
SHADOW（全部只记账）
→ 启用 STANCE（只影响姿态，无内容，错了代价最小）
→ 启用 LIGHT
→ 启用 EXPLICIT
→ 启用 HIGHLIGHT（最后）
```

为什么 HIGHLIGHT 最后：这五种方式的出错代价不对称。错过一次本可以说的温暖旧事，对话只是平淡了一点；但在错误的时刻主动提起旧事——比如在用户只想被安静陪着的时候翻出往事——会造成真实的冒犯和信任损伤。**代价小的先启用试错，代价大的最后启用**，这是分级启用制度的唯一理由。

每一级的启用门槛（回放测试通过、反事实抽样合格）在 SPEC 中定义为可核查的指标，不靠感觉判断。

## 什么时候才动工

本模块受两层纪律约束，均已在既有文档中生效：

1. `docs/SOFT_RETRIEVAL.md` 的七条开工门槛；
2. `docs/IMPLEMENTATION_HANDOFF.md` 的阶段门——本模块属于"禁止顺手实现"，开工不早于阶段 4 通过。

阶段 4 通过后的第一个实现物**不是**接入 Telegram 的运行链，而是一个完全离线的回放器（regressions 测试台），规格见 [`REPLAY_HARNESS.md`](./REPLAY_HARNESS.md)。它不连 TG、不碰真实记忆、不注入任何回复——代码写错最多影响实验，不影响真实对话。

## 术语表

| 术语 | 含义 |
|---|---|
| 正史 / canon | 经过审核的正式记忆（episodes.jsonl）。原文永不因检索优化改写。 |
| Episode | 一条正式记忆：一段有叙事重量的完整事件，含原话、时间、意义。 |
| SHADOW / 影子模式 | 全链运行但结果不交给主模型，只记账。用于零风险积累评估数据。 |
| Trace | 影子运行的记账数据库。实验日志，不是记忆，永不作为检索源。 |
| 载荷 / Payload | 真正可能交给主模型的那段文字。按表达方式分级供给。 |
| 亮点 / HIGHLIGHT | AI 主动说出的独特温暖旧事。风险最高，最后启用。 |
| 启用 | 某种表达方式通过评估验证，获得影响真实回复的许可；可随时撤销或降级。 |
| 回音壁 | 记忆通过 AI 自己的复述自我增强的循环。 |
| 拉线 | 用户主动提起旧事（如"你还记得吗"），是 EXPLICIT 的唯一触发条件。 |
| 车道 | 不同来源的记忆（正式/边界/画像/自记/候选）各自独立的检索权限，不同分竞争。 |
| 回放 | 用固定测试案例离线重跑检索与判定，比较不同配置的成绩。 |
| 冻结集 | 不允许随意查看和修改的测试案例集，防止"背答案"。 |
| 独立证据 | 在 AI 近期未提及相关内容的情况下，用户自发说出的信息。模式置信度晋升只认它。 |
