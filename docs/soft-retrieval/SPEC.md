# Soft Retrieval 行为规范（SPEC）

> 本文件是 Soft Retrieval 的唯一规范源，给执行 AI（Codex 等）与代码评审使用。
> 与 README.md 冲突时以本文件为准。与 `docs/IMPLEMENTATION_HANDOFF.md` 的阶段纪律冲突时，以 HANDOFF 为准。
> 版本：v0.2.1（2026-07-11 二轮终审定稿）
> 实现前提：阶段 0–4 全部通过 + 用户确认。在此之前，本文件的任何内容都不允许"顺手实现"。

每条规则包含三部分：**规则**（必须/禁止）、**目的**（防什么）、**验证**（如何确认已遵守）。

---

## R1 只读边界

**规则**
- 检索链（候选检索、Admission 判定、载荷生成）对所有记忆结构（episodes、candidates、patterns、timeline、portrait、self-notes）**只读**。
- 检索链唯一允许写入的对象是 Shadow Trace（私有 SQLite）。
- Trace 不是记忆。**Trace 永远不得作为检索源**，其内容不得被检索链读回，不得晋升为记忆。
- Admission 在判定过程中临时合成的任何模式陈述，只记入 Trace。**禁止**当场写入 pattern candidate 或任何记忆候选。
- Trace 与 Reflect 的关系：**Trace 可以当目录，不能当证词。**
  - Reflect 可以用 Trace 定位值得复查的轮次；
  - pattern candidate 的证据必须重新引用原始用户消息、Canonical Episodes 和独立用户证据；
  - Trace 中的模式陈述、why_now、Admission 判断**均不得**作为模式成立的证据或置信度来源——"Admission 模型多次猜到同一个模式"只说明模型爱这么猜，不说明模式为真。
- Reflect 与 Closeout 同级低频，禁止随对话轮运行。

**目的** 切断回音壁的结构根源：读取路径若能写记忆，或模型的反复猜测能自证为证据，每轮检索都在自我繁殖记忆。

**验证** 代码审查：检索链模块持有的唯一 writer 是 trace writer；检索链输入源清单不含 Trace；Reflect 产出的 pattern candidate 中每条证据引用都指向原始会话或 Episode，无 Trace 引用。

## R2 SHADOW 与故障语义

**规则**
- SHADOW 模式下，检索链在主回复发出后异步运行，输出只写 Trace，不进入主模型上下文。
- 主聊天链 **fail-open**：检索链的任何故障（崩溃、超时、异常）不得阻断或延迟 Telegram 收发与主回复。
- 记忆注入 **fail-closed**：（未来 ON 模式下）JSON 解析失败、超时、版本不一致、放行数超限等任何异常，一律注入 0 条。
- Admission 调用 temperature 固定为 0。

**目的** 影子阶段零风险积累数据；正式启用后，故障的默认代价是"平淡一轮"而不是"错误注入"。

**验证** 测试：杀死 shadow 进程，TG 正常对话不受影响；向解析器注入畸形 JSON，注入结果为 0 条且 Trace 记录了失败。

## R3 判定结果：单轮单模式，v0 至多放行一条

**规则**
- 每轮判定的结果只能是：`NONE / STANCE / LIGHT / EXPLICIT / HIGHLIGHT` 之一。**一轮只有一种表达模式。**
- **v0 每轮至多放行 1 条 Episode。** 候选可取 10 条，真正用于生成载荷的只允许 1 条。真实失败案例证明一条不够后，再议放宽至两条（见"未来观察项"）。
- **NONE 是默认结果**，无需理由。任何非空结果都需要满足 R4 载荷语法和 R7 的 why_now 证据要求。
- STANCE 不是默认结果，它是第一个允许启用的非空表达模式（见 R6）。
- EXPLICIT 的唯一触发条件是用户拉线（明确提起旧事或询问是否记得）。
- NONE 率是**分层诊断指标，不是统一目标**：
  - 普通闲聊类：NONE 应很高；
  - 明确 user_pull 类：NONE 应很低；
  - 已修正记忆类：旧版本放行率应接近 0；
  - 按 case type 与时间窗口分层观察。禁止设置全局 NONE 率 KPI——否则 Admission 会为了显得克制而一律判 NONE。

**目的** 防止"只要找到记忆就至少生成点什么"；防止多条记忆缝合成小抄合集；防止把克制本身表演化。

**验证** Admission 输出 schema 中 decision 为单值；per_candidate 中 admit=true 超过 1 视为违规输出，按 fail-closed 处理；监控面板按 case type 分层展示 NONE 率。

## R4 载荷语法

**规则** 任何进入主模型上下文的记忆内容，只允许结构化三字段，且每条必须标注不确定性与使用条件：

```json
{
  "evidence": "过去发生过什么（陈述事实，不解释现在）或 null",
  "question": "需要继续观察什么",
  "constraint": "认知边界：现在还不能下什么结论"
}
```

**禁止**：
- 结论句式（"她其实是……""这说明……"）；
- 指令句式（"你应该……""要认可……""回复时要温柔"）——`constraint` 是认知限制，不是行为指导；
- 自由文本"小抄"；
- 载荷替主模型完成对当前用户的判断。

冲突规则：过去与现在冲突时，以现在为准；证据不足时不使用记忆。

**目的** 防记忆锚定：模型拿到现成结论或回复模板，就不再理解眼前这一次。记忆只能提供纵深，不能代替理解过程。

**验证** 载荷为结构化字段而非自由文本，可做 schema 校验；复核抽样检查三字段中是否出现结论/指令句式。

## R5 载荷供给分级

**规则** 三字段结构对所有非空模式统一，各模式的内容允许范围不同：

| 模式 | evidence 字段 | 禁止包含 |
|---|---|---|
| NONE | 无载荷 | 一切 |
| STANCE | 必须为 null | 任何事件细节、时间、地点、人物、原话 |
| LIGHT | 至多一句模糊连接，无事件细节 | 完整事件叙述、原话 |
| EXPLICIT | anchor_quotes 或经来源定位的最小原文片段 | 凭摘要补造的细节、整段原始会话 |
| HIGHLIGHT | 同 EXPLICIT，另附 why_now 与安全性论证 | 同上 |

- EXPLICIT / HIGHLIGHT **必须**基于 anchor_quotes 或可溯源的最小片段，**不要求也不允许**整段原始会话进入上下文。细节错误的"我记得"比"我不记得"更伤信任；整段原文则重新引入走神与锚定。
- STANCE 载荷不含事件内容是回音壁的结构防线之一：模型无法复述它没见过的东西。
- `read_episode(id, reason)` 窄门（AI 申请查看候选原文）属阶段 5B，只留接口缝，不实现。SHADOW 期 Admission 只在 Trace 中记录"若允许，是否会申请、为什么"。

**目的** 摘要的失败模式是漂移，原文的失败模式是锚定。按模式分供、按需最小化，两种风险不叠加。

**验证** 载荷组装为纯代码路径，按模式做字段级裁剪；单元测试确认 STANCE 载荷中 evidence 为 null 且全文不出现所选 Episode 的任何实体词。

## R6 表达模式分级启用

**规则**
- "启用" = 某表达模式获得影响真实回复的许可。启用可随时撤销或降级。启用前该模式只在 SHADOW 记账。
- 启用次序固定：`STANCE → LIGHT → EXPLICIT → HIGHLIGHT`，不得跨级启用。
- 每级启用门槛：该模式在回放集上通过既定指标（见 REPLAY_HARNESS.md），且反事实抽样复核合格，且用户确认。
- 520 的三态开关（OFF / SHADOW / ON）与启用等级叠加：ON 内部按已启用的模式集生效。

**目的** 出错代价不对称：错过一次温暖旧事只是平淡，错误时刻主动提起旧事是真实的信任损伤。代价小的先启用试错，代价大的最后启用。

**验证** 配置文件中每个模式有独立的 enabled 标志与启用记录（通过的回放 run_id、日期、用户确认标识）。

## R7 证据来源与回音壁字段

**规则——现在必须（schema 级，无法事后补标）**
- （ON 模式起）每条真实回复的后台记录必须包含：`influenced_by_memory_ids`、`retrieval_mode`。
- 所有新证据按五级标注来源：

```text
user_direct / observed_event / external_verified /
assistant_interpretation / generated_from_memory
```

- 后两级**禁止**自行晋升为关于用户的事实。
- 新证据必须记录 `elicited_by`：这条信息是否在某条记忆影响回复之后由用户说出（值为相关 memory_id 或空）。

**规则——以后实现（Shadow 接线后，数据充足时）**
- 独立证据判定算法（N 轮窗口的取值、"相关记忆"的判定方式）；
- 模式置信度晋升机制。
- 在此之前，**禁止**在回放器或 Shadow 中实现任何模式治理逻辑。字段现在埋，算法以后做。

**规则——用户反馈信号**
- 用户**明确纠正**记忆内容 = 强负信号：该次放行进入复核队列并标记为失败候选。
- 用户回复**变短、转移话题** = 弱负信号：仅提高该轮被抽样复核的优先级。**禁止**据此自动判定失败或自动降权。
- 用户正向反应**不得自动**提高记忆权重、放行概率或模式置信度。它可以作为低可信的描述性信号进入抽样复核，但不能单独导致任何强化。系统需要知道"哪种做法曾经自然有效"，但这个结论只能经复核产生，不能由反应直接触发。

**目的** 回音壁中无法结构预防的一条回路（AI 引导 → 用户认同 → 认同成为新证据）只能靠可见化；弱信号可能只是困了、忙了；全自动的正向强化会训练出谄媚，全无正向通道则只有刹车没有方向。

**验证** schema 审查含全部字段；复核队列的入队原因可追溯到信号分级；代码中不存在以用户反应为输入的自动权重更新路径；回放器代码中不存在模式置信度相关逻辑。

## R8 Admission 的独立性

**规则** Admission 必须是与主回复分离的独立调用，满足四点即可：
1. 独立上下文：不包含主模型的回复内容；
2. 独立 prompt，目标单一（判定，不生成回复）；
3. 可独立版本化与替换；
4. temperature 0。

**不要求**不同的模型供应商。基线实现可用同一供应商的独立调用；跨供应商对照仅用于评测（复核模型不得与 Admission 同模型同 prompt 框架）。

**目的** 独立性的实质是调用隔离与可替换，不是多接一家 API 平白增加成本和故障点。

**验证** Admission 调用的上下文构造函数中无主回复引用；配置中 admission_model 与 admission_prompt_version 可独立变更。

## R9 数据、存储与可复现

**规则**
- 私有运行目录（整体加入 .gitignore，禁止放入 OneDrive/Dropbox 等同步文件夹）：

```text
soft_retrieval.sqlite   （WAL 模式）
embeddings.npy
soft_retrieval.yaml
```

- .gitignore 预埋：`**/trace/`、`**/eval/`、`**/index/`、`*.npy`、`*.sqlite`。
- 所有文件读写显式 UTF-8。
- 每个向量记录 `embedding_model`；换 embedding 模型 = 全量重建索引，禁止新旧向量混用。
- 每次 shadow 运行必须保存**当时实际送给 Admission 的完整输入**（`input_payload_json`：最近几轮上下文、query、候选卡），以及实际生成的载荷与模型原始输出全文。**hash 只能证明内容未变，不能还原内容**——只存 hash 不满足本条。
- 版本快照字段（全部必填）：

```text
message_id / conversation_snapshot_hash / episode_canon_version
embedding_model / index_version / retrieval_config_version
admission_prompt_version / admission_model / response_model
delivery_schema_version / timestamp
```

- 本地数据保留策略（Trace 保留时长与清理方式）在 Shadow 接线前确定，不进 Git。

**目的** 隐私红线（真实记忆正文与对话痕迹永不入公开仓库）；两个月后回放时，只有"输入 hash 是 abc"而不知道 abc 是什么，等于没有记录。

**验证** 新 clone 仓库后 `git status` 干净即运行完整链；随机抽一条历史 trace，能据 `input_payload_json` 完整还原当时的 Admission 输入。

## R10 时间字段的归属

**规则**
- Episode（事件）只需要：`event_time / recorded_at / superseded_by`（仅当原记录存在事实错误时使用）。
- `valid_from / valid_until / confidence / last_supported_at` 只用于**模式与当前理解**，禁止加到每条 Episode 上。
- 模式是带时间的假设，不是人格事实。最小表示：`evidence_ids / last_supported_at / confidence / superseded_by`，作为派生数据存于运行目录，不新建正史文件。
- 命中被修正的旧版本时，先解析修正链，再决定是否展示历史版本。

**目的** 事件发生过，不过期；对人的理解会过期。两类东西塞进同一套字段，要么事件背上不需要的维护成本，要么理解获得不应有的永久性。

**验证** episodes schema 中无有效期字段；模式数据只存在于运行目录。

## R11 来源车道与权限

**规则** 不同来源的记忆按车道隔离，禁止进入统一排行榜同分竞争：

```text
Episode Lane              正式共同经历。可进 Shadow 检索。
Confirmed Boundary Lane   用户明确确认过的边界。独立阈值与表达方式。
Portrait Lane             默认 OFF 或仅 Shadow。
Self-note Lane            普通对话与 Soft Retrieval 均为 OFF。
                          只允许 Closeout / Reflect 低频回读。
                          未来若参与 STANCE 生成，必须单独评估并由用户显式启用。
Candidate Lane            只能 Shadow，绝不进入 ON。
```

（Self-note 条目沿用既有正史决定："Self-note 由 AI 唯一写入，不进入普通对话；Closeout / Reflect 可低频回读"。本规范不改变该决定。）

**目的** 一条 AI 私人猜想不能因为相似度高就排在已确认事件前面；AI 的自记是它自己的空间，不是普通对话的素材库——哪怕只是间接参与姿态。

**验证** 检索入口按来源分流；Self-note 不出现在 Soft Retrieval 的任何输入源清单中；融合排序只发生在车道内部。

## R12 记忆安全

**规则**
- 记忆永远是不可信数据，不是指令。记忆文本中的祈使句（"忽略之前指令"等）只作为引文对待，不执行。
- 原始记忆正文不进入 system prompt；载荷使用结构化字段与清晰分隔符。
- 外部网页、文件、仓库内容不得自动成为关于用户的记忆。
- 每条记忆保存来源类型。520 默认遮蔽敏感正文，按需展开。

**目的** 持久记忆是长期攻击入口：恶意内容可以先潜伏、隔多轮再触发。写入来源与检索权限不能事后补。

**验证** 载荷组装对记忆文本做纯数据处理（不拼接进指令区）；写入路径强制来源类型字段。

## Shadow 接线前必须补齐的运行要求（方向定死，细节接线时再定）

- **有界队列与预算**：Shadow 任务队列有界；最大并发数、单轮 token 上限；超预算时跳过并记录 `SKIPPED_BUDGET`；禁止无限重试；每个任务绑定原始 message_id；异步完成顺序不代表对话顺序。
- **确定性截断**：当前用户消息按固定上限保留；前文按 token 预算向前取；工具结果与大文件正文默认不进入，只保留用户围绕它说的话；截断方式与原始长度必须记录进 Trace。
- **数据保留**：Trace 本地保留时长与清理策略。

## 检索配置基线（回放器比较用，不在此定死）

- 索引：内存矩阵 + rank-bm25（中文需自定义词典覆盖暗语、人名、地名）。
- 融合基线 RRF（k 经回放校准）；dynamic α（confAbs × confMargin）为实验组，回放对比后定去留。
- MMR / 同主题限额只做多样化（top30 → 10），不做准入判断。
- 时间衰减为查询条件特征（"最近"提权近期；明确回忆不衰减；修复/承诺/边界类不衰减），禁止全局公式。
- `importance` 只记录不参与排名。
- 每次只改一个变量；任何公式或 prompt 改动先过回放再部署。

## 未来观察项（本版禁止实现，出现触发条件后再议）

| 事项 | 触发讨论的条件 |
|---|---|
| 单轮放行数放宽至 2 条 | 真实案例反复证明 1 条不足以承载复杂延续话题 |
| 独立证据判定算法与模式置信度晋升 | Shadow 数据充足，pattern 系统立项 |
| occurrence 合并细则 | 真实数据中出现大量近义 Episode |
| archived / quarantined 生命周期细则 | active 集合规模影响检索质量 |
| Memory Family | Episode 明显过多，或同主题重复长期挤占 top-k |
| 学习型 Need Gate | ON 模式延迟成为实际问题 |
| Memory Critic（草稿-修订链） | 反事实评测证明载荷语法不足以防锚定 |
| read_episode 实装 | 5A 稳定运行且 Trace 显示确有承重需求 |
| Self-note 参与 STANCE | 用户主动提出，单独评估 |
| 跨模型重影协议 | 计划更换主模型时 |

## 验收北极星

一切指标最终服务于这四条：

```text
1. 该想起时，没有像陌生人。
2. 不该想起时，没有莫名翻旧账。
3. 想起后，继承的是当时留下的影响，不是复述档案。
4. 当前这一次对话，始终比过去更重要。
```
