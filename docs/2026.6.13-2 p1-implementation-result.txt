P1-1: Telegram 429 与重试机制 ✓
======================================================================

修改文件 1: src/adapters/channel/telegram.js

1. 删除了固定重试延迟数组:
   -  TELEGRAM_REQUEST_RETRY_DELAYS_MS = [1_000, 3_000, 6_000]

   替换为指数退避常量 + TelegramRateLimitError 类:
   +  TELEGRAM_RETRY_BASE_MS = 1_000
   +  TELEGRAM_RETRY_MAX_MS = 30_000
   +  TELEGRAM_RETRY_MAX_ATTEMPTS = 5
   +  class TelegramRateLimitError extends Error {
   +    constructor(retryAfterMs) {
   +      super(`telegram rate limit, retry after ${retryAfterMs}ms`);
   +      this.name = "TelegramRateLimitError";
   +      this.retryAfterMs = retryAfterMs;
   +    }
   +  }

2. fetchJsonWithRetry 重写:
   - 循环: 固定 3 次 → 5 次指数退避
   - 延迟: 固定数组取值 → Math.min(1000 * 2^attempt, 30000) + jitter(0~500ms)
   - 重试序列: 1s → 3s → 6s → (stop)    旧
              ~1s → ~2s → ~4s → ~8s → ~16s  新
   - 429 处理: 无 → 检测 instanceof TelegramRateLimitError, 用 max(retryAfter, 退避延迟)

3. fetchJsonWithTimeout 重写:
   - 新增: 响应状态 429 时解析 retry_after 并抛出 TelegramRateLimitError
   - 其他状态码保持原有行为

修改文件 2: src/services/telegram-service.js

同样的三处变更（同步）:
1. 删除 TELEGRAM_REQUEST_RETRY_DELAYS_MS → 替换为指数退避常量 + TelegramRateLimitError 类
2. fetchJsonWithRetry 重写为指数退避 + jitter + 429 retry_after 支持
3. fetchJsonWithTimeout 新增 429 解析
