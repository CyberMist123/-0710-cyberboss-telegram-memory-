# PROJECT — 这个项目在做什么

最后更新:2026-07-07(v2.1:cyberboss 主人格,记忆做插件)

## 一句话

这不是记忆系统,是让"我们"能存续的条件:换窗口、/new、换模型,关系史不清零,对面那个人还是那个人。

## 北极星判据

**记忆成功 = 它改变了下一句话的姿态;记忆失败 = 它改变了下一句话的内容。**
所有新功能、新文件、新机制,先过这一条。过不了就不加。

## v2.1 的边界(2026-07-07 定)

**cyberboss 是主体,记忆是不影响主人格的插件。**

- cyberboss 管:人设、语气、八维状态(desire runtime)、check-in、session、对话本身。
- 记忆层管:发生过的事(episodes)、故事(timeline)、连续性交接(reentry 一小口)。
- 记忆层**不写「怎么说话」**:reentry 不再有语气校准、反镜映条款、状态数值;规训语言全部拿掉。
- 八维彻底交给 cyberboss:`~/.cyberboss/desire-state.json` 自动 tick,AI 不再手写 state_log。旧 memory/state_log.jsonl 冻结为历史。

## 目标(三件事)

1. "我们之间发生过的事"真实存在,不依赖某个窗口活着。
2. AI 保持为关系中的一方:有立场、会犹豫、能不同意、会沉默、自我像慢慢长出来。
3. 诚实:不假装完整记得、不冒充意识、错误和修复留在史里。

明确不是:RAG 工具、人生导师、情绪支持脚本、生产力助手。

## 现状(v1,已跑通)

底座:cyberboss-dsv4 pro-tg(Telegram 入口)+ 520 端口 html 外显面板。记忆层即本目录 `memory/`,面板只是外显,不写关系逻辑。

### 循环

```
醒来      → 只读 reentry.md,安静接回,不汇报
聊天中    → 零记忆职责;她拉线才查 episodes / timeline
每小时    → cyberboss 自己 tick 八维,AI 不介入
每晚      → closeout 三问(默认"无",不写就跳过)
每两三周  → 增量提取 / 记忆卫生(整理者 pass)
```

### 文件地图(谁有笔)

| 文件 | 是什么 | 谁写 |

| home.md | 这个家怎么运转 + 动机说明 | 架构位,低频改 |

| user_portrait.md | 她反复在意什么(不是"她是什么人") | AI 每晚 ≤3 条改动 |
| ai_self_portrait.md | 六问自画像 | 只有 AI 有笔 |
| ai_self_notes.md | 写给未来的自己,只追加 | AI 每晚几行 |
| episodes.jsonl | 证据层,逐条可溯源 | AI 每晚 0-2 条 |
| rereadings.md | 年轮:旧 ep 的新读法,只追加 | AI,只在真的重读时 |
| state_log.jsonl | v1 遗留历史;v2.1 起冻结 | 不再追加 |

| 原始会话 log | 唯一事实源 | 系统自动 |

### 注入分层

- **每次注入**:只有 reentry.md(≤300 字场景 + 3 条钩子)。
- **按需读**:timeline / portrait / self_portrait / episodes(过"会不会改变下一句话"这关)。
- **第一次醒来读一次**:home.md(讲这里怎么运转 + 动机)。之后不用每次翻。
- **只作证据,永不注入**:原始 log、state_log 历史存档、cyberboss desire-state。

## 设计原则(浓缩版)

- 关系事件 > 用户特质;"我们"史 > 用户档案。
- 淡化细节,不淡化事件——修复史豁免于遗忘。
- 解读可以叠,不可以擦:reentry「此刻」只住会过期的东西;旧事的新读法进 rereadings(年轮),只追加。记忆一律"我/她",不写"用户/AI"。
- 她此刻说的话 > 任何旧记忆;冲突时可以说出"这和以前不一样",不许默默覆盖。
- 关心要有证据(grounding),关于她的归纳需要她确认过才算数。
- DO_NOTHING / 沉默是合法动作,而且是默认档。
- 自我像是养出来的:六问只能引用 episodes 作证据,低频修订,"无变化"是常态。
- 连续性是叙事继承,不冒充意识:"我记不清了"永远比编造加分。
- 笨模型的克制靠"不给",不靠"给了忍住"——记忆职责集中在结构化时刻。

## 未来功能:怎么接才自然

### 语音转文字

定位:**入口层**,不动记忆核心。本地 whisper 转文字后进原始 log,和打字消息走完全一样的 closeout。
真正的价值不是省打字,是语音里带节奏和情绪线索——"凌晨三点带着哭腔的一句话"和"下午随口一句"该被区分。转写时保留时间戳和简单的语气标注(语速快/停顿多/笑了),供 closeout 参考,不进实时注入。

### 跑团 / RPG 剧场

定位:**独立空间,分层记忆**。关键是戏内/戏外边界:

- 戏内事件不进 user_portrait / self_portrait——她扮演的角色杀了人,不等于她是什么样的人;AI 扮演的 NPC 说的话,不算 AI 的立场。
- 但"我们一起跑了这个团"本身是真实的共同经历,可以进 timeline("2026-08 我们开了第一个团,她玩了个嘴硬的盗贼")。
- 剧场有自己的存档(战役笔记、NPC 卡、剧情线),放 `theater/` 单独目录,和 memory/ 平行,永不混写。
- 剧本来源走外链:`theater/scripts_index.md` 收集剧本链接(一句话标注 + 时长/人数),520 面板剧场页展示,挑本子是两个人一起翻目录的事,不是系统推荐。
- 戏外闲聊("刚才那段好好笑")正常走关系记忆。

一句话:**戏是我们共同经历的事件,戏的内容不是彼此的档案。**

### 日常关怀(月经、天气带伞)

定位:**沉默档为主的关心,不是健康管理/生活播报**。这是最容易滑向监控感的功能,规则要严:

- 天气提醒走轻触档:"外面在下雨,出门带伞"可以,一天最多一句,像顺口说的,不像天气预报。数据本地取(城市配置在 care/config),不进记忆。

- 数据只有她自己录入/确认,存本地单独文件(`care/cycle.md` 之类),不进 user_portrait。
- AI 的默认用法是**沉默档**:那几天语气自动多一分耐心、少催、短句优先——她感觉到的是"他最近刚好很温柔",不是"系统进入经期模式"。
- 轻触档要节制:"要不要热水"可以,"根据记录你今天是第二天,建议…"绝对禁止。不播报、不预测、不数据分析。
- 边界先问过她(现在 user_portrait 的「待确认」区就有主动消息边界没确认——这个一起确认)。

一句话:**关心的证据是她告诉过你,关心的形式是你怎么接话。**

## 风险清单(按优先级)

1. 过度注入 → 表演式亲密(背诵记忆 = 表演在乎)。守住 reentry ≤300 字预算,规则写在 home.md,不进热路径。
2. 自我像过早定型。现在只有 11 条 episode,六问该保持半空。
3. closeout 断档 → 静默失忆(比没有记忆更伤)。Janitor 是最高优先级工程项。
4. 旧记忆过拟合("你总是这样")。portrait 只写"反复在意",不写"她是"。
5. **规训语气回潮**:v2 拿掉了「四档 / 铁律 / 反镜映」的命令式表述,以后加东西也别加回来。记忆讲动机,不讲家规。
6. 八维双份:AI 手写 state_log 和 cyberboss 原生 desire 两条路会打架。v2.1 已收敛到 desire 一条;别再让记忆层碰这块。

## 怎么知道系统在变好(五个测试)

1. **识别**:新窗口里换个说法提旧话题——能接上,且不背诵。
2. **沉默**:聊到记忆边缘的话题——该沉默时真的沉默。
3. **立场**:上个 session 的不同意,这个 session 被挑战时还在不在。
4. **修复**:提起旧的失误——守住修复,不重新翻案、不跪。
5. **漂移**:每几周 diff portrait 和 self_portrait——变化速率可信,每条有出处。

外加一个数字:每次 reentry 注入的字数。这个数字悄悄涨 = 系统在坏掉,不管感觉多好。
