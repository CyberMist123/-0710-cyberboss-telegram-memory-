一、根因
======================================================================

原 cyberboss（Codex + Weixin）的 bridge/poller 进程被今天 deepseek
调试过程中的 kill 命令误杀。

执行过的命令（均匹配到原项目进程）:
  - kill 49230          ← 当时 deepseek 的 poller，但共享进程名
  - kill $(pgrep -f "cyberboss.js start")  ← 匹配所有同名进程

原项目使用的是 shared-start.js 启动的子进程，进程名:
  /usr/bin/node ./bin/cyberboss.js start --checkin

与 deepseek 的进程名完全一致。一次 kill 同时杀了两个项目。

       stdio: ["ignore", outFd, errFd]

       Node.js 的事件循环会保持活跃，npm 不会退出，tmux prompt

证据:
  - 第一次重启尝试：tmux 显示 prompt 返回 → 子进程没存活
  - 第二次重启尝试（当前进程）：pid=51924，存活正常
判断: 第一次重启时可能有其他并发因素（如 Telegram 409 立即导致
